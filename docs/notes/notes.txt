Section 1: URLs and navigation

- The home page is `/`, and `listing_render_view` in `marketplace/views.py` loads it.
- The navigation bar is in `templates/marketplace/partials/_header.html`, included by
  `templates/marketplace/base.html`. Its links use `{% url %}`.
- Listing cards link to their detail pages with `get_absolute_url()` in
  `marketplace/models.py`. The detail route is in `marketplace/urls.py`, and
  `ListingDetailView` in `marketplace/views.py` loads the listing by its primary key.
- The detail page uses `templates/marketplace/listing_detail.html`.
- Screenshots: `section1_home_page.png`, `section1_navigation.png`,
  and `section1_listing_detail.png`.

Section 2: Database queries and search

- Added two distinct search forms:
  1. `BrowseForm` (GET) in `marketplace/forms.py`: Designed for public marketplace browsing where query parameters stay visible in the URL so results can be bookmarked and shared. Handled by `filtered_listings()` in `marketplace/browse.py`. Results are shown in `templates/marketplace/partials/_results.html`, which also explains when nothing matches.
  2. `PurchaseHistorySearchForm` (POST) in `marketplace/forms.py`: Designed for signed-in buyers to search completed orders in `templates/marketplace/buyer_purchase_history.html`. It uses POST with CSRF verification specifically to hide query parameters from the URL and browser history for privacy.

- Seller listing inquiry counts use Django's `annotate()` with `Count` and `__` to query related conversations and buyers, and appear in `templates/marketplace/seller_listings.html`.
- Verified both empty result edge cases and user-specific results. Screenshots: `section2_get_search.png`, `section2_orm_summary.png`, and `section2_post_search.png`.

Section 3: Static files and styling

- `moveon/settings/base.py` tells Django where the project's `static/` files live, and
  shared templates use `{% load static %}` to include them.
- The main stylesheet, `static/css/marketplace.css`, imports the smaller stylesheets in
  `static/css/marketplace/`. Images and browser JavaScript are in `static/img/` and
  `static/js/`. Listing photos uploaded by users are handled separately through Django's
  media settings.
- The existing layout, colors, fonts, header, and listing cards are still in place.
  Some CSS and JavaScript links use a version such as `?v=a3-1`, which prompts the browser
  to load the updated file. Screenshot: `section3_static_css.png`.

Section 4: Vega-Lite Charts

- The profile page embeds a Vega-Lite bar chart and cumulative line chart for total earned
  vs. total spent, plus a stacked answered/unanswered inquiry bar chart for top listings.
- Vega-Lite specs are available at `/vega-lite/earned-spent.json` and
  `/vega-lite/earned-spent-timeline.json` and `/vega-lite/listing-inquiries.json`. Each
  spec uses a URL-backed data source rather than inline values. Authenticated JSON data
  is served by endpoints under `/api/profile/charts/`.
- PNG chart outputs are available at `/vega-lite/earned-spent.png`,
  `/vega-lite/earned-spent-timeline.png`, and `/vega-lite/listing-inquiries.png`.
  They are generated from the same Vega-Lite specs and private API data.
- Vega-Embed renders the specs in `templates/marketplace/profile_base.html`; its browser
  module is loaded from jsDelivr, so the local browser needs internet access for that
  library. The chart encodings are Vega-Lite specs validated in the Vega-Lite Editor;
  Django supplies the same-origin API URL at runtime. The chart data comes from the
  signed-in user's database records.
- `seed_bundle_inventory` creates seven inquiry threads across six Maya listings, with four
  answered and three unanswered. Gray Rug has one of each, so its stacked bar shows both
  response states. The seed also creates three completed purchases totaling $113. The
  command is idempotent; transactions and inquiry/message read states are stored in models.

Section 5: Forms and user input

- Marketplace search uses GET. New listings use `ListingCreateView` in
  `marketplace/views.py` and `ListingCreateForm` in `marketplace/forms.py`.
  `templates/marketplace/listing_form.html` displays the form and includes a CSRF token.
- Django shows the form on GET, then checks and saves it on POST. The bundle builder and
  summary pages also handle GET and POST requests.

Section 6: JSON API

- `listings()` in `marketplace/api.py` provides a public, read-only GET endpoint at
  `/api/listings/`. It returns active listings as JSON with each listing's IDs, title,
  price, condition, category, and detail URL. Seller email addresses and private messages
  are left out.
- The endpoint supports the marketplace search filters and returns up to 20 results per
  page. It returns a JSON error for invalid filters. `marketplace/access_middleware.py`
  allows public access to this route while keeping messaging APIs protected.
- `listings_documentation()` uses the same API data at `/api/listings/demo/`, where the
  filters can be tried and the response type viewed. Regular pages return `text/html`,
  the API returns `application/json`, and the chart returns `image/png`.
- The README includes the API details and example URLs. Screenshot: `section6_json_api.png`.


Week 4:

Section 1: Internal API and Vega-Lite Charts

- The public internal JSON endpoint `GET /api/listings/` returns clean, database-backed
  JSON for active listings. In A4 mode, the three JSON endpoints under
  `/api/profile/charts/` publicly return only the fictional Maya demonstration data.
  No sign-in or registration is required. Existing account routes redirect home.
